## Decisions

1. **Human rulings applied:** raw files are kept under `warehouse/raw/` (gitignored); v0 keeps only the latest value, with `vintage` recorded; CSVs stay in git; the next-day DAM is included once published; Python 3.14.
2. **Next-day DAM:** DAM files include any later operating day that is already published and complete. The header lists it, and `vintage` records the publish time where the ISO gives one: the ERCOT document time, otherwise the file's HTTP Last-Modified. The row counts above include those days. For ERCOT the 30-day window is unchanged from session 1 (3,600 and 14,400 rows).
3. **Windows use each ISO's local operating day:** America/Los_Angeles for CAISO, America/New_York for NYISO and ISO-NE, America/Chicago for ERCOT and SPP, and EST for MISO, which publishes its market day in EST all year. Runs straddling midnight Pacific therefore gave CAISO a window one day earlier on the first run.
4. **15-minute means:** the 5-minute RT prices from CAISO (RTD), NYISO (RTD), SPP and ISO-NE become time-weighted 15-minute means, variable `lmp_rtm_15m_mean`, rounded to 4 decimals. With regular 5-minute intervals this is the plain mean of exactly three prices; a quarter hour missing any price fails the file.
5. **NYISO irregular intervals:** NYISO stamps prices at interval end and adds extra RTD intervals at irregular times (for example 09:47:51, or 12:10:03 in place of 12:10). Each interval runs from the previous stamp to its own, is weighted by its length, and is split at quarter-hour boundaries. No interval may exceed 5 minutes, so a missing stamp is never bridged. I hand-checked CAPITL 2026-09-23 09:45 EDT against the raw file: 9.8325.
6. **CAISO RT uses RTD 5-minute, not the native 15-minute FMM,** following the prompt's 5-minute rule. See open question 3.
7. **MISO RT is hourly.** gridstatus can only reach MISO 5-minute RT for today and yesterday, and the weekly 5-minute final files lag one to two weeks, so 30 days of 5-minute data are not reachable without an API key. The connector uses MISO's hourly real-time ex-post LMPs: the final report where published, the prelim report otherwise, named per row in `source`.
8. **Nodes:**
   - NYISO: the 11 internal zones; external proxies (H Q, NPX, O H, PJM) are excluded.
   - MISO: the 8 `*.HUB` names. gridstatus's "Hub" type also includes about 400 other nodes.
   - SPP: gridstatus lists two hubs.
   - ISO-NE: the 8 `.Z.*` zones plus `.H.INTERNAL_HUB`.
   - Entities use the native ids unchanged: `nyiso:N.Y.C.`, `isone:.Z.MAINE`.
9. **geo** is one code for single-state ISOs, and the ISO footprint as a list for MISO, SPP and ISO-NE. I entered those lists by hand; see open question 2.
10. **Provenance:** a row's `source_url` is the one data file that supplied its day. A per-ISO pattern ignores helper requests, such as ISO-NE's cookie page and NYISO's latest-interval file. Where several files supplied a day, as with SPP interval files, the row cites the report page and the run log lists the files.
11. **SPP speed:** SPP daily RT files are 51 MB, served at about 0.1 MB/s. They are fetched 8 at a time, with 5-minute interval files as the fallback for days whose daily file isn't posted.
12. I added `--out-dir` so trial runs can go to scratch space; the smoke tests ran there, outside the repo. `warehouse/raw/isone_test/` is a leftover from a debugging probe (one ISO-NE file, gitignored).

## Errors hit

1. **MISO RTM not written.** The 2026-09-24 hourly prelim (`docs.misoenergy.org/marketreports/20260924_rt_lmp_prelim.csv`) and the final report both returned 404, most recently at 07:57 UTC. The file will pass on a rerun once MISO posts that day.
2. **SPP RTM not written.** The daily RTBM files for 09-21 to 09-24 are not posted (404). The interval fallback then hit interval files that are absent at SPP, for example `By_Interval/21/RTBM-LMP-SL-202609211520.csv`, which was still 404 on recheck while known-good files downloaded fine. Separately, the SPP portal sometimes returns an empty 200 response; retries recover those.
3. **ISO-NE RTM not written.** gridstatus reads only ISO-NE's preliminary 5-minute files. All 180 downloaded with status 200, but they contain gaps: 13 quarter hours per node are incomplete, for example the 12:00 to 16:00 file for 09-15 jumps from 14:00 to 15:55. gridstatus also silently skips a 4-hour file that fails to load; the completeness check catches that case too.
4. **NYISO RTM failed twice before passing.** First, a plain 3-per-quarter mean met irregular stamps. Second, my "every regular stamp present" rule rejected 12:10:03. Fixed per Decision 5. The failed runs' logs are kept.
5. **CAISO OASIS reset connections** when I probed several ISOs in parallel. Sequential runs, with gridstatus's 5-second sleep and my retries, had no errors.
6. **My bug:** after a redirect, `requests` re-enters `Session.send`, so each file was recorded twice. That made every day look like two files, and rows cited the report page instead of the file. Values were unaffected. It is fixed, and CAISO, NYISO, MISO and ISO-NE were rerun. SPP's run predates the fix but reads through pandas (urllib), so it was unaffected.
