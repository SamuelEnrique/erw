Same non-negotiables: real data only, fail loudly, no em dashes, never delete existing files, commit after each task, do not push, do not stop to ask questions. ANTHROPIC_API_KEY from .env.

Build tool 20 v0: a question-answering layer that never states a number it did not fetch.

TASK 1. Tools for the model. In warehouse/chat/tools.py, define four tools over the erw package (local backend by default, Supabase or Redivis when ERW_BACKEND is set): list_tables (with sector and license filters), describe_table (columns, entities, variables, date range, source, license), query (table, optional entity, variable, start, end, and an aggregation from a fixed list: latest, mean, median, min, max, percentile with a value, count, sum, plus a group_by of year, month, day, hour or entity; returns a small result table and the citation), and compare (two queries side by side). No free-form SQL. Every result carries table name, data version and source report.

TASK 2. The loop. warehouse/chat/ask.py: pick the current Sonnet-class model from the models list; a system prompt built from package/llms.txt that states the rules (answer only from tool results, cite every number with its table and source, say "not in the warehouse" when it is not, prefer public tables and label internal ones as internal); a tool-use loop of at most 8 calls; then a post-check that every number in the final answer appears in some tool result (allowing rounding to the stated precision), and if any does not, one retry with the violation named, then refusal. Print token usage and cost per question. A CLI: python warehouse/chat/ask.py "question".

TASK 3. Evaluation set. warehouse/chat/eval/questions.yaml with 30 questions whose answers you compute independently with pandas from the CSVs, across sectors and shapes (for example: yesterday's day-ahead average at ERCOT HB_NORTH; the ISO with the highest real-time max last week; ERCOT HB_HUBAVG peak-block IQR 2015 versus 2025; number of operating gas generators in Texas by nameplate MW; Henry Hub close on a given date; a question whose answer is not in the warehouse). eval.py runs every question through ask.py and scores: exact number match within tolerance, citation present and correct, refusal correct where applicable, and reports accuracy, cost and mean tool calls. Run it and record the results; do not tune on the eval set after seeing results, only fix outright bugs and say which.

TASK 4. A read-only API route in site/ (app/api/ask) that calls the same loop with the anon key backend, rate-limited to 10 questions per IP per hour, plus a minimal /ask page with the question box, the answer, and the citations rendered, matching the site design. Do not wire a public model key into the browser; the route runs server-side with ANTHROPIC_API_KEY from the environment.

TASK 5. SESSION_12_REPORT.md in the usual format with the eval results table, the cost per question, and the failure cases verbatim. Final commit.
