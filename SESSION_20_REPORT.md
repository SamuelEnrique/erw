**The four misses of the first run, and what was fixed:**
1. **s20q10 and s20q12: a bug in tool routing, fixed.**
   - **What happened:** the model asked `query` for a local operating day (for example `start 2026-09-20`, `tz America/Chicago`). The tool read those dates in the time zone (05:00Z to 05:00Z) and returned the next day's row (55.24 instead of 50.3679; 13.32 instead of 15.5906).
   - **Why:** tables of daily or longer rows label each day at 00:00Z of its date (Decision 11).
   - **The fix:** a date bound on a series table whose rows are all P1D, P1W, P1M or P1Y is now that date in UTC. Hourly and shorter tables still read local days. The fix is in `warehouse/chat/tools.py` and the site's `site/lib/chat/tools.ts`, and the `start` description says so.
2. **s20q14: a bug in the query tool, fixed.** `sum` over `value_column: dollars` was refused as "not numeric". The column holds numbers with blanks for "not stated", and arrives as text. It now aggregates when every non-blank value is a number. The site's copy already converted numbers.
3. **q14: not a tool bug, not changed.** The answer's number was right (261,586), but its prose said "00:00Z to 23:00Z". The literal number check found 23 in no tool result and refused the answer. The check is literal by design (session 12). In the second run the model phrased it without the hour, and it passed.

## Decisions

1. **One list of pages drives the nav, the home page, `/about` and `/data`,** so they cannot drift apart.
2. **A `<details>` nav, not a script menu:** it works without JavaScript and needs no state.
3. **The weekly brief is not regenerated for the EIA revision.** A published brief is a dated record.
4. **The 45-question set recomputes the original 30 from today's tables.** Only q27 moved, and freezing the old answer would score a correct reading of today's table as wrong.
5. **The second evaluation run was made after the fixes** (USD 1.1177, within the stop), so the reported accuracy is of the code as committed.
6. **The overview is generated, not written,** so "no number typed by hand" holds on every rebuild.
