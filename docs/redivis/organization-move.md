## What the ERW changes after the move (a diff, not applied)

Only if the owner changes; nothing here is done before it.

```diff
--- a/warehouse/redivis/config.yaml
+++ b/warehouse/redivis/config.yaml
-owner_kind: user            # REDIVIS_OWNER is a Redivis user account (redivis.user), not an organization
+owner_kind: organization    # REDIVIS_OWNER is Ben Domingue's Redivis organization (redivis.organization), since <date of the move>
```

- **`REDIVIS_OWNER` becomes the organization's name** in the three places it is set: the GitHub secret (read by `.github/workflows/daily-prices.yml`), this machine's `.env`, and the code machine's `.env`. `upload.py`'s `account()` already takes either kind (`redivis.organization(owner)` when `owner_kind` is not `user`), so no code changes.
- **The API token**: `REDIVIS_API_TOKEN` must belong to an account that can edit the organization's datasets; if the owner's token cannot, a token of an organization member with edit access replaces it in the same three places.
- **The address**, only if it changes: `site/data/site.json` (`redivis.url`), the citation line of `docs/redivis/release-v1/README.md` (regenerated by `release_v1.py`'s `readme()`), and `docs/redivis/release-v1.md`'s first paragraph. `/data` reads `site.json`, so its link and its "How to cite a table" follow.
- **The check after**: `python warehouse/redivis/upload.py --reconcile` (read only) must find every draft table where it was.

**What the refusals have done to the draft.** The uploader deletes a draft table before it uploads its new copy (Redivis uploads append, so this is its only true replace) and removes the new, empty table when the upload fails. Release v1 now marks it "held: Redivis storage" beside `node_basis_daily` (session 385). While the storage stands, any growing table whose upload is refused leaves the draft the same way; each day's refusal is now a skip, not a failure (session 377), so it will not show as a red day.
