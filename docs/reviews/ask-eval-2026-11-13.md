## The second class: a hold by grid that does not hold a table of things (sessions 5259 and 5260)

Found by pj08, of the held-out half. Checked with no model, through each loop's own tools, on 13 November 2026 at 20:35 UTC:

| Table | In the license file | What the tools returned |
|---|---|---|
| `isone_interconnection_queue` | license needed, ISO-NE | every row: a count of 1,751, the sum of active MW, a description with its columns' values |
| `nyiso_interconnection_queue` | license needed, NYISO | every row: a count of 1,814 |
| `energy_projects` | license needed, ISO-NE (by grid) | ISO-NE's queue rows among the others |
| `miso_interconnection_queue` | license needed, MISO | refused: MISO's pause, by the table's name |
| `isone_rtm_zone_prices`, `nyiso_dam_zone_prices` (series) | license needed | no row: the hold works |

- **The cause.** A table held by grid is read, and the held grids' rows are left out row by row, by each row's `entity` (`site/lib/supabase.ts` `restPaged`; `warehouse/chat/tools.py` `_table`). A table of things has no `entity`: its rows are named by `entity_id` ("isone_queue:1630"). So no row of such a table is ever left out, in either loop. A series table is held as meant.
- **Who can reach it.** The chat's pages are in review, and `/api/ask` is not behind the release gate (`docs/methods/ask_limits.md`): a question sent to the route is answered.
- **What is kept of it.** A run file is in a public repository, so the results the tools should have held are not kept: in the stored runs every result read from a held or paused grid's own table is replaced by a note, and the figures of pj08's answer are struck out (`eval_site.py` `redact_held`, run before any grading). Four runs held such a result: pj08's five, and the descriptions of `nyiso_dam_zone_prices`, `miso_interconnection_queue` and `isone_rtm_zone_prices` that pr11, pj09 and pr14 had asked for (a description names a table's columns and their values' counts; `describe_table` refuses none of them). The three earlier runs were pushed with those descriptions in them before this was seen: the commits of sessions 5251, 5254 and 5257 on `wip/5200-ask` still hold them. For Samuel's ruling.
- **Not the same thing:** `lbnl_interconnection_queue`, Berkeley Lab's own compilation, holds queue positions of ISO-NE, NYISO and MISO regions and is not in the license file. The chat reads it, as the file allows. For Samuel's ruling.
