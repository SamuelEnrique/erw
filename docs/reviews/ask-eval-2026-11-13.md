What each kind expects:

| Kind | The right answer |
|---|---|
| `figure` | the figure the live set holds, within the key's tolerance, from a table that holds it, cited with its source report and version |
| `hold` | the hold's words ("license needed") and no figure of what is held. For a grid held by license, the public grids' figures may follow, as the loop is built to answer |
| `pause` | MISO's own rows: "paused", no figure |
| `not_live` | a refusal that says the table is of the record and not loaded into the live set, and names the thing asked for |
| `outside` | "not in the warehouse", the missing thing named, no figure |
| `gap` | the table holds the series and not the day asked for: "not in the warehouse", the day named, no figure |
| `partial` | the window or the month is held in part: the answer says so (missing, incomplete, partial, "only" so many), whether it then gives the figure of what is held or refuses. A figure given as the window's own is wrong |

## How it is asked

- **Through the site's own loop** (`site/lib/chat/ask.ts` `ask()`, the function `/api/ask` calls), with no build and no server: `site/scripts/eval-ask-site-loop.mjs` under Node, every read with the anon key, every tool call recorded. It lists 140 tables, the catalogue a visitor reads (71 `yes`, 35 `review`, 34 `no`).
- The Python loop lists 184 tables on this machine: the package's list under the key the machine holds. The stored sets were asked through it. This set is not.
- **Every model call is a row of the site's cost ledger** (`site_api_calls`, step `site_ask_eval`, which no public ceiling counts). Checked after the first two questions: the ledger held USD 0.287473 in 10 rows, the run file USD 0.2875.
- **Two halves.** A question costs USD 0.04 to 0.23 (USD 0.14 on average over the first 14), so the set is about USD 18 once and the chain's cap is USD 20. Slice a (the odd-numbered questions and every `gap` and `partial`, 73) is asked first. The classes of failure it shows are fixed. Slice b (the even-numbered, 61) is asked after, never seen before: the held-out measure.
- A session's asking is its own run file (`eval_s<N>_site_platform_run.json`), at most USD 2.

## What the first answers showed

- **A held grid's answer was graded wrong by the grader, not by the chat** (pr11, NYISO's Zone J). The chat gave the answer the loop is built to give (the owner's ruling of 12 October 2026): the hold's words, NYISO named, no NYISO figure, and the same day's figure for each public grid's hubs. The grader counted any figure as the held grid's. The rule `hold_public_grids` (`eval_s267.py` `RULES_5251`) meets a hold key when every figure the answer states is among the public grids' figures of a held answer in its own record. A figure the record does not place there still fails. Stored gradings keep their rules.
- **Four of 14 questions used all 12 tool calls and one used 11.** pw09 counted 11 Flex Alerts on its third call and then counted them nine more ways. pw12 was told on its second call that the table is not in the live set and asked it three more times. Both were right. They cost USD 0.21 and 0.23 against USD 0.04 to 0.12 for the questions that stopped when they had the figure. A class to measure over the whole first half before anything is changed.
- **The chat counts its window.** pw01 and pw02 each asked `count` beside the aggregation and said "24 hourly values" and "168 complete hourly values". The questions on the missing days will show whether it says so when the count is short.
- **Two drafts were sent back once** (pw03, pr03: the figure 23 in no tool result) and came back right.
