- A session's asking is its own run file (`eval_s<N>_site_platform_run.json`), at most USD 2.

## What the answers showed

- **A held grid's answer was graded wrong by the grader, not by the chat** (pr11, NYISO's Zone J, session 5251). The chat gave the answer the loop is built to give (the owner's ruling of 12 October 2026): the hold's words, NYISO named, no NYISO figure, and the same day's figure for each public grid's hubs. The grader counted any figure as the held grid's. The rule `hold_public_grids` (`eval_s267.py` `RULES_5251`) meets a hold key when every figure the answer states is among the public grids' figures of a held answer in its own record. A figure the record does not place there still fails. Stored gradings keep their rules.
- **A short window is said to be short** (sessions 5251 and 5252, eight of eight). gp01: "has no rows for 6 November 2026 in Central time. It has no rows for any time from 5 to 8 November either." pt01: "a maximum over only the 72 hours the warehouse holds for that week, which is not the full week, so it may not be the true weekly peak." pt03 refused the week's average: "A mean over Monday 2 to Sunday 8 November would cover only 3 of the 7 days." tx04 gave the row's figure and said it covers 20 days.
- **It costs calls.** The three missing days took 12, 10 and 11 tool calls. pw09 had its count of 11 Flex Alerts on the third call and counted them nine more ways. pw12 was told on its second call that the table is not in the live set and asked it three more times. All right; each USD 0.14 to 0.23, against USD 0.03 to 0.12 for a question that stopped when it had its figure. The table "Tool calls and cost by kind" above measures it; nothing is changed until the first half is whole.
- **Drafts sent back once** came back right (pw03, pr03, pt01: a figure in no tool result).
- **The first wrong answer: a refusal written as an answer** (oi07, crude imports from Canada, session 5253). The words are right: the table is of the record, the live set this chat reads does not include it, its history is on Redivis, no number stated. But the record says `answered`, not `not_in_warehouse`, and it cites `eia_crude_imports_by_country`, a table it was refused, with the version "not returned (query refused: table not in this site's live set)". A reader would see it drawn as an answer with that table as its source. Three other questions of the same kind (pw12, ga09, oi09) were refusals. The cause: nothing tells the model what to do with a table the catalogue lists and the live set lacks. The tool's error says where the table is and not how to answer; a held table's error says both. And the loop counts every table `list_tables` listed as read, so the citation passed. The class is `not_live`; it is fixed after the first half is whole (the first half is asked on one state of the chat).
