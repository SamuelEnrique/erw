## Why the guard was a blockade

The guard did its job: it refused red commits. But the red came from page files the data machine commits every day (`board.json`, the seller's capture file), and the data machine's own commit path (`warehouse/run_data_machine.sh`, `dm_commit`) runs only each group's own tests, not the suite (chain 208's note asked for the guard there; the desktop's chain did not add it). So the data machine pushed the files that made the suite red, and the bots that check the suite were stopped by them. Session 3751 adds the guard to `dm_commit` (chain 208's three lines) so a page-file commit that would make main red goes to `wip/red-dm-<day>` instead.
