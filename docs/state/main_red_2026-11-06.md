## Spell 1: tests pinned to dated page files

- **The trigger:** `137e9dfb7` rewrote `site/data/datacenter/*` and the Research cards. Reproduced here:
  - at its parent, `test_session701`, `test_session709` and `test_session720` passed (15 tests);
  - at `137e9dfb7`, 2 failures and 1 error (11 tests run).
  - The All grids tab's node figures need `node_basis_daily` to hold 90 percent of the days of the hub's twelve months. The twelve moved forward, and the table's day-ahead days stop at 20 October (session 2863's report).
- **The calendar added more.**
  - From 1 November, `test_session174` required each card's `computed_at` to begin "2026-10-", and the data machine recomputes the cards daily. Its own run then put every recomputed card back (`dm_test_findings`).
  - From 2 November: `test_session422` (the datacenter mirror's twelve months rolled: 34.07 against the pack's 33.73), `test_session190_replication` (HB_NORTH held 671 of October's 744 hours, because the runner stopped on 30 October) and `test_session144_page` (it wanted exactly 149 CAISO months).
- **Why nothing stopped it.**
  - The data machine's commit path (`warehouse/run_data_machine.sh`, `dm_commit`) ran each group's own tests (`dm_test_*`), not the suite, and pushed.
  - Nothing else ran the suite on main until the daily workflow's first step, "merge tests", the next day.
- **Why no one saw it for six days.**
  - "Merge tests" failed on every run from 31 October (runs 41208065020 and 41227279353 on 31 October). `warehouse/health.py` recorded its reason as the last error-looking line, "Warning: The 'generic' unit for NumPy timedelta is deprecated", not the failing tests. Session 2864 changed the line it takes.
  - The job stayed green on GitHub, because `health.py run` records the failure and the later steps' `if:` skip them. So the daily run committed nothing from 31 October to 5 November, and GitHub showed success.

## Spell 2: the catch-up run's commit

- **The trigger:** `e2794ff06`, the first daily commit since 30 October. Reproduced here:
  - at its parent, the eight modules below passed (87 tests, 9 skipped);
  - at `e2794ff06`, 8 failures and 4 errors:
    - `test_session505`: 3, the license record has no row for `ercot_wind_solar_hsl_monthly`;
    - `test_session94`: 2, CAISO's mix (`test_california_holds_the_months_of_the_hydro_gap_from_caisos_own_data` among them);
    - `test_session1139`: 2;
    - `test_session98`, `test_session133`, `test_session275`, `test_session378` and `test_session1118`: 1 each (the board's spreads, the spark spread, the curtailment profile, the coverage words).
- **Cause 2a: a new table without its records.** The run added `ercot_wind_solar_hsl_monthly` to coverage. Its license row (`warehouse/metadata/license_tables.csv`) and the package's table list were not written with it, and nothing in the run checks that they agree before the commit.
- **Cause 2b: the thin rebuild, root-caused in the runner's restore step.**
  - The run was the first of November, so the monthly builders ran on the runner (`warehouse/run_monthly.sh`).
  - `warehouse/scheduled.py` lists each builder's input tables: the runner restores the ones named for restoring, and skips a builder whose named inputs are missing.
  - `mix_profile`'s list named `caiso_fuel_supply` and `carbon_intensity_hourly`, but the builder also reads `caiso_fuel_supply_history` for California's hydro gap (October 2019 to August 2020).
  - On the runner that table is absent and unnamed, so the step ran. The builder logged "the months of the hydro gap stay EIA's and are not held" and wrote CAISO's mix from 90 months to 80.
  - The board's hourly files and the curtailment profile were rebuilt from the runner's shorter windows the same way.
- **Why nothing stopped it.**
  - The daily workflow's commit step pushed straight to main, with no suite run on the commit.
  - GitHub's merge gate (`.github/workflows/code-branch.yml`) tests a `task/` branch's own head, not the branch merged with the main it lands on. The last branch it tested (`task/2869-combined`, run 42144016506) was cut before `e2794ff06`, so main's red state was first met by a landing's local gate (session 1439's).

## Not changed by this chain, and why

- **The data machine's own commit path** (`warehouse/run_data_machine.sh`, before `git push --quiet origin main`). The edit was refused by this machine's permission classifier, and the script is the desktop's. The change, for the desktop's chain:
  ```
  if ! "$PYTHON" scripts/push_guard.py --who "data machine daily" --step "dm_commit" --red-branch "wip/red-dm-$day"; then
    echo "the suite failed on the commit: committed here, pushed to wip/red-dm-$day, not to main"
    exit 0
  fi
  ```
  It goes after the `git pull --rebase` block and before `git push --quiet origin main`. This is the path of spell 1's trigger.
- **The Roundup's push** (`.github/workflows/roundup.yml`, `git push origin HEAD:main`): the periodicals chain's file. The same three lines apply.
- **Cause 2a's check before the commit** (a table in coverage without its license row): `test_session505` holds it. With the guard, the commit goes to `wip/red-daily-<day>` instead of main, and the daily red email names it.
